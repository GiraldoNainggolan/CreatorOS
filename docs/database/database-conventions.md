# Database Engineering Standards

This document defines the strict physical database engineering conventions for CreatorOS. These standards ensure consistency, performance, and strict adherence to the architectural decisions (`ADR-001` to `ADR-005`), particularly our distributed Modular Monolith constraints.

## 1. Identity & Primary Keys
- **UUID Policy**: All primary keys and identity references must be **UUIDv7**. UUIDv7 provides temporal sorting, improving database insert performance and B-tree index locality compared to UUIDv4.
- **Generation**: UUIDs are strictly generated by the application layer (Laravel) before insertion, ensuring the application holds identity prior to persistence.
- **Primary Keys**: Every table must have a primary key named `id` of type `uuid`.

## 2. Relationships & Constraints
- **Intra-Module Foreign Keys**: Physical Foreign Key (FK) constraints are **REQUIRED** for relationships strictly *within* the same bounded context (e.g., `script_parts.script_id` referencing `scripts.id`).
- **Cross-Module References**: Physical Foreign Key constraints are **FORBIDDEN** across bounded contexts. Module isolation is paramount (`ADR-002`). Cross-module references are soft links (e.g., `content_item_id` in `gate_evaluations` is just an indexed `uuid` column with no database-level FK constraint).
- **Unique Constraints**: Used to enforce domain invariants (e.g., globally unique keywords). Naming convention: `unq_<table_name>_<column_name>`.
- **Check Constraints**: Used heavily to enforce basic data integrity before the application layer. Naming convention: `chk_<table_name>_<description>`.

## 3. Naming Conventions
- **Tables**: Plural, `snake_case` (e.g., `brand_profiles`, `script_parts`, `qa_checklists`).
- **Columns**: `snake_case` (e.g., `order_index`, `is_critical`). 
- **Indexes**: `idx_<table_name>_<column_name>`.
- **Foreign Keys**: `fk_<table_name>_<column_name>`.
- **Migrations**: Standard Laravel convention `YYYY_MM_DD_HHMMSS_create_<table_name>_table`.

## 4. Time & Audit
- **Timezone Policy**: All dates and times must be stored in **UTC**.
- **Timestamp Policy**: Use PostgreSQL `timestamptz` (timestamp with time zone) to ensure proper UTC conversion and storage.
- **Audit Policy**: Every table must include `created_at` and `updated_at` timestamps. High-compliance aggregates (like QualityGate) may require append-only log tables (e.g., `StageHistory`).
- **Soft Delete Policy**: Implemented via a `deleted_at` (`timestamptz`) column. Soft deletes are used to preserve referential integrity for cross-module metrics and historical data (e.g., Deactivated Pillars).

## 5. Advanced PostgreSQL Features
- **JSONB Policy**: Strictly reserved for **Value Objects** and unstructured data (e.g., `Demographics`, `Metrics`, `ColorTokens`). DO NOT use JSONB to store relationships, primary domain entities, or data that requires frequent relational joins.
- **Enum Strategy**: Use `varchar` combined with `CHECK` constraints (e.g., `CHECK (status IN ('Draft', 'Ready', 'Locked'))`) that map 1:1 with Laravel Backed Enums. This prevents the schema migration overhead associated with native PostgreSQL ENUM types while maintaining database-level integrity.
- **PostgreSQL Extensions**: No special extensions required for UUIDv7 if generated application-side. If native generation is required in the future, standard Postgres 17+ or extension updates will be evaluated.

## 6. Performance Guidelines
- **Index All References**: Every column used as a reference (`uuid`), whether an intra-module physical FK or a cross-module soft link, MUST be indexed.
- **Index Soft Deletes**: Queries will frequently filter by `deleted_at IS NULL`. Partial indexes should be evaluated for heavily queried active tables.
- **GIN Indexes for JSONB**: If a specific key within a `JSONB` Value Object is frequently queried (e.g., querying `AnalyticsSnapshot` by a specific metric threshold), a GIN index must be applied.
- **Avoid Over-Indexing**: Do not index text columns or boolean flags unless they are the primary driver of a highly trafficked read query.
